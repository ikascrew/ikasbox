## Project Overview

ikasbox is a Go server + React SPA for managing video/image content (groups, projects, thumbnails) used by the ikascrew VJ ecosystem. It stores metadata in SQLite (`ikasbox.db`) and uses GoCV (OpenCV) for thumbnail generation, so a working OpenCV install is required to build the Go side. Documentation and comments are largely in Japanese; the project is a work in progress and is currently mid-migration from server-rendered Go templates to a React frontend (branch `react`).

## Commands

### Go server

```
cd cmd
go run main.go init            # create SQLite database (fails if ikasbox.db exists)
go run main.go start           # start the server on port 5555
go run main.go group ...       # group subcommands: register, import, check, list (remove is a stub)
go run main.go project ...     # project subcommands: register, list, add
```

- Flags (defined in `cmd/main.go`): `-db <file>` (default `ikasbox.db`), `-ext <patterns>` (import extensions, default `*.mp4,*.mpeg,*.png,*.jpg,*.jpeg`). A DB filename can also be embedded at build time via `-ldflags "-X main.embedDB=xxxx.db"`.
- `cmd/develop.sh` runs the server with `skewer` for live reload during development.
- Tests: `go test ./db/` (only `db/content_thumbnail_test.go` exists). Run a single test with `go test ./db/ -run TestName`.

### React frontend (`frontend/`)

```
npm run dev      # Vite dev server on http://localhost:3000, proxies /api, /thumb, /content/media to :5555
npm run build    # production build to frontend/dist (not checked in)
npm run preview  # preview the production build
```

Development flow: run the Go server (port 5555) and `npm run dev` together; the dev server proxies API calls. `frontend/dist` is the build output and is gitignored; the Go server does not yet serve it (production wiring is still TODO — the React migration is in progress).

## Architecture

### Go side

- `cmd/main.go` — CLI entry point; parses flags/args and calls `ikasbox.Start()`.
- `ikasbox.go` (package root) — dispatches subcommands (`start`, `group`, `project`, `init`). `start` opens the DB, launches a multicast server (`github.com/ikascrew/core/multicast`, server name "ikasbox") in a goroutine, then starts the HTTP server. `group.go` / `project.go` at the root implement the CLI subcommands.
- `contentimport/` — directory-scan + register + GoCV thumbnail-generation logic, shared by the CLI (`ikasbox group import`, which wraps it with an interactive confirm + progress bar) and the web API (`v1/groups/import`, which runs it in a background goroutine and returns immediately — no progress reporting). `ImportDirectory(groupId, path, extensions)` is the one-shot entry point; `SearchFiles`/`RegisterFile` are the composable pieces if you need per-file control (e.g. a progress bar).
- `config/` — global singleton config set via functional options (`config.Set(opts...)` / `config.Get()`). Defaults: port 5555, DB `ikasbox.db`.
- `db/` — data layer over SQLite. Files ending in `_gen.go` are **generated by argen** (`cmd/argen.exe`, ActiveRecord-style ORM) — do not edit them; hand-written logic goes in the corresponding non-`_gen` file (e.g. `db/group.go` vs `db/group_gen.go`). Tables: groups, contents, content_thumbnails, projects, project_groups. `db.Transaction(fn)` wraps a function in begin/commit/rollback.
- `handler/` — legacy server-rendered HTML routes (`/`, `/content/...`, `/group/...`, `/project/...`, `/thumb/`) using Go templates.
- `handler/internal/` — templates and static assets embedded via `go:embed` from `_assets/` (served at `/js/`, `/images/`, `/css/`). Changing anything under `_assets/` requires rebuilding the binary.
- `handler/api/` — JSON API for the React frontend. Routing is a map in `api.go` `init()` from path (e.g. `v1/groups/view`) to a `Parameter` factory; each endpoint is a struct implementing `Parameter.Processing() (Return, error)`, with request JSON unmarshaled into the struct. To add an endpoint: define the parameter/return structs in the relevant file (`group.go`, `project.go`, `content.go`) and register it in `apiMap`. Content list/detail endpoints use `groupId == -1` as a sentinel for "all groups" (mirrors the legacy synthetic "すべてのコンテンツ" group) — see `ContentView.Processing` and `db.SelectPagingContent`.
- The legacy `/content/media/{id}` route (video streaming) is still the only way to stream video bytes; the React frontend's content-view page points its `<video>` tag directly at it. Vite's dev proxy only forwards the exact `/content/media` prefix, not `/content` — proxying the bare `/content` prefix would also swallow the frontend's own `/contents` SPA route.

### React side (`frontend/src/`)

- Class-based React 18 components with MUI (Material UI), react-router-dom v6, and axios (wrapped in `API.js`; all calls are POST/PATCH/DELETE JSON to `/api/v1/...`).
- Built with Vite (`vite.config.js`, entry `index.html` → `src/App.jsx`). Files containing JSX use the `.jsx` extension; plain modules (`API.js`, `Util.js`, `Paging.js`) stay `.js`. Follow this convention for new files — Vite/rollup requires JSX to be in `.jsx`/`.tsx` files.
- `App.jsx` mounts the app; `pages/Pages.jsx` defines routes; `pages/Layout.jsx` / `LayoutDialog.jsx` provide shared chrome; feature pages live under `pages/Projects/`, `pages/Groups/`, `pages/Contents/`; shared widgets under `components/`.

# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

ikasbox is a Go server + React SPA (Material UI) for managing video/image content (groups, projects, thumbnails) used by the ikascrew VJ ecosystem. It stores metadata in SQLite (`ikasbox.db`) and uses GoCV (OpenCV) for thumbnail generation, so a working OpenCV install is required to build the Go side. Documentation and comments are largely in Japanese. The old server-rendered Go template UI (MDL) has been removed; the Go server now only serves the JSON API plus the embedded React build.

## Commands

### Go server

```
cd cmd
go run main.go init            # create SQLite database (fails if ikasbox.db exists)
go run main.go start           # start the server on port 5555
go run main.go group ...       # group subcommands: register, import, check, list, remove
go run main.go content ...     # content register <group-id> <name> <type> [params-json] — generated (plugin) contents
go run main.go project ...     # project subcommands: register, list, add, remove
```

- Flags (defined in `cmd/main.go`): `-db <file>` (default `ikasbox.db`), `-ext <patterns>` (import extensions, default `*.mp4,*.mpeg,*.png,*.jpg,*.jpeg`). A DB filename can also be embedded at build time via `-ldflags "-X main.embedDB=xxxx.db"`.
- `cmd/develop.sh` runs the server with `skewer` for live reload during development.
- Tests: `go test ./db/` (only `db/content_thumbnail_test.go` exists). Run a single test with `go test ./db/ -run TestName`.
- Frontend tests: `npm test` (in `frontend/`, runs `vitest run`). See the React frontend section below.
- **`npm run build` (in `frontend/`) must be run at least once before `go build`/`go run` on a fresh checkout.** The React build output is `go:embed`-ed directly into the `handler/internal` package (see below) — the embed directive fails to compile if that directory has no files in it. A placeholder `.gitkeep` is committed so a pristine clone still compiles; after the first `npm run build` the real build output satisfies the embed.

### React frontend (`frontend/`)

```
npm run dev      # Vite dev server on http://localhost:3000, proxies /api, /thumb, /content/media to :5555
npm run build    # production build, output straight into handler/internal/_assets/spa (embedded by the Go server)
npm run preview  # preview the production build
npm test         # vitest run — unit/component tests, jsdom environment
```

Development flow: run the Go server (port 5555) and `npm run dev` together; the dev server proxies API calls. In production, `go run main.go start` alone serves everything: the built React SPA (embedded from `handler/internal/_assets/spa`) plus the JSON API — no separate static file server or `npm run dev` needed.

## Architecture

### Go side

- `cmd/main.go` — CLI entry point; parses flags/args and calls `ikasbox.Start()`.
- `ikasbox.go` (package root) — dispatches subcommands (`start`, `group`, `project`, `init`). `start` opens the DB, launches a multicast server (`github.com/ikascrew/core/multicast`, server name "ikasbox") in a goroutine, then starts the HTTP server. `group.go` / `project.go` at the root implement the CLI subcommands.
- `contentimport/` — directory-scan + register + GoCV thumbnail-generation logic, shared by the CLI (`ikasbox group import`, which wraps it with an interactive confirm + progress bar) and the web API (`v1/groups/import`, which runs it in a background goroutine and returns immediately — no progress reporting). `ImportDirectory(groupId, path, extensions)` is the one-shot entry point; `SearchFiles`/`RegisterFile` are the composable pieces if you need per-file control (e.g. a progress bar). `RegisterGenerated(groupId, name, type, params)` registers a **generated content** (no backing file, e.g. type `cd`/`terminal`): it validates the JSON `params` by actually instantiating the plugin via `github.com/ikascrew/plugin/video` and renders the 17 thumbnails from plugin frames. Content types use the plugin registry's canonical vocabulary (`file`/`img`/`cd`/`terminal`; `video.Normalize` absorbs legacy `"image"` rows).
- `config/` — global singleton config set via functional options (`config.Set(opts...)` / `config.Get()`). Defaults: port 5555, DB `ikasbox.db`.
- `db/` — data layer over SQLite. Files ending in `_gen.go` are **generated by argen** (`cmd/argen.exe`, ActiveRecord-style ORM); hand-written logic goes in the corresponding non-`_gen` file (e.g. `db/group.go` vs `db/group_gen.go`). NOTE: `cmd/argen.exe` (2017, pre-modules) no longer regenerates anything on this setup — schema changes are applied by hand-editing the `_gen` file following its exact mechanical pattern (see the `params` column in `content_gen.go`: Select list, Build, Save insert/update maps, Update/UpdateColumns, fieldValueByName/fieldPtrByName, columnNames). Tables: groups, contents (incl. `params` TEXT for generated contents), content_thumbnails, projects, project_groups. `db.Open` runs an idempotent `migrate()` that `ALTER TABLE`s missing columns into existing DBs. `db.Transaction(fn)` wraps a function in begin/commit/rollback.
- `handler/` — three routes plus SPA/API mounting: `/content/media/{id}` streams video bytes (`contentPlayHandler`), `/thumb/{id}[/{seq}]` streams a thumbnail JPEG (`thumbnailHandler`), and `/project/content/list/{id}` (`projectContentListHandler`, `handler/project.go`) returns a `ProjectResponse{Project, Contents}` JSON. That third route was never part of the legacy HTML UI — **`github.com/ikascrew/server` and `github.com/ikascrew/client` (sibling repos) both import `handler.ProjectResponse` directly and hit this exact URL** (`server/config/config.go`'s `load()`, `client/tool/project.go`'s `getContentList()`) to build their local project/content caches during `create`. Do not remove or reshape this route/type without updating those two repos in lockstep. Everything else that used to be server-rendered HTML (top page, group/project list & add, content list/detail) has been replaced by the React SPA + `handler/api`.
- `handler/internal/spa.go` — `go:embed`-s the React production build (`_assets/spa`, populated by `npm run build`) and serves it at `/`, falling back to `index.html` for any path that isn't a real static asset so react-router's client-side routes work on a hard refresh/deep link.
- `handler/api/` — JSON API for the React frontend. Routing is a map in `api.go` `init()` from path (e.g. `v1/groups/view`) to a `Parameter` factory; each endpoint is a struct implementing `Parameter.Processing() (Return, error)`, with request JSON unmarshaled into the struct. To add an endpoint: define the parameter/return structs in the relevant file (`group.go`, `project.go`, `content.go`) and register it in `apiMap`. Content list/detail endpoints use `groupId == -1` as a sentinel for "all groups" — see `ContentView.Processing` and `db.SelectPagingContent`.
- Vite's dev proxy only forwards the exact `/content/media` prefix, not `/content` — proxying the bare `/content` prefix would also swallow the frontend's own `/contents` SPA route.

### React side (`frontend/src/`)

- Class-based React 18 components with MUI (Material UI), react-router v7 (the unified `react-router` package, not `react-router-dom`), and axios (wrapped in `API.js`; all calls are POST/PATCH/DELETE JSON to `/api/v1/...`).
- Built with Vite (`vite.config.js`, entry `index.html` → `src/App.jsx`). Files containing JSX use the `.jsx` extension; plain modules (`API.js`, `Util.js`, `Paging.js`) stay `.js`. Follow this convention for new files — Vite/rollup requires JSX to be in `.jsx`/`.tsx` files.
- `src/theme.js` — the single shared MUI `createTheme()`; `App.jsx` wraps everything in `ThemeProvider` + `CssBaseline`. Adjust palette/typography/shape here rather than per-component overrides.
- `App.jsx` mounts the app; `pages/Pages.jsx` defines routes; `pages/Layout.jsx` (AppBar + permanent `Drawer`) / `LayoutDialog.jsx` provide shared chrome; feature pages live under `pages/Projects/`, `pages/Groups/`, `pages/Contents/`; shared widgets under `components/`. There is no more custom layout CSS (`css/App.css`/`css/Layout.css` were removed) — styling goes through the theme and MUI's `sx` prop.
- Tests are colocated `*.test.js`/`*.test.jsx` files (e.g. `pages/Paging.test.js`, `components/LoadingButton.test.jsx`) run via `vitest.config.js` (jsdom environment, `src/setupTests.js` wires up `@testing-library/jest-dom`). Prefer plain unit tests for pure logic (`Paging.js`, `Util.js`) and `@testing-library/react` render tests for components that don't need a live API — components that call `API.*` on mount aren't covered yet and would need mocking `axios`/`API.js` first.
